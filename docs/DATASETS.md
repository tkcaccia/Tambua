# Dataset acquisition and evaluation contract

## MoNuSAC 2020

The [organizer release](https://monusac-2020.grand-challenge.org/Data/) provides H&E images and expert nuclei contours for epithelial cells, lymphocytes, macrophages and neutrophils. The [MedOtter Parquet conversion](https://huggingface.co/datasets/MedOtter/MoNuSAC2020) preserves instance and type maps with patient barcodes. Both sources state CC BY-NC-SA 4.0; raw images and annotations are intentionally excluded from this MIT code repository. The two pinned Parquet files total 277,453,464 bytes, representing 209 train and 101 test images. The split folders contain 46 and 25 patient IDs, but **two IDs occur in both**, leaving 69 unique IDs in these files. SHA256 is checked by `tambua download-monusac` before use:

- train `c0d7c0c99600e960a38ed92e67cfa93a80eafb68186d8b958d90a8452dc9cbda`;
- test `196566e3bf4ddc06d880e244864c27f1b60b3db91a421b0daa0465ff81bf382f`.

The eight locally extracted examples contain 2,079 scored nuclei across eight distinct patients. Each split includes all four classes, but the small test example has very few neutrophils; it is a data-path demonstration, not a powered benchmark. The mirror gives 40× nominal magnification but no verified pixel size for these files. CellPhenotyper/GigaTIME inference requires a separately verified physical calibration and must not silently assume 0.25 µm/pixel.

The original organizer archives were subsequently checked on Chiamaka with [`scripts/audit_monusac_original.py`](../scripts/audit_monusac_original.py). All **209 training** and **101 test** `.svs` headers agree with their paired expert XML `MicronsPerPixel` values. Training spacing ranges from **0.19448 to 0.2527 µm/pixel**; test spacing from **0.2456 to 0.2527 µm/pixel**. The training archive SHA-256 is `5b7cbeb34817a8f880d3fddc28391e48d3329a91bf3adcbd131ea149a725cd92`. There are 91 training and 32 test ROIs at least 512 pixels in both dimensions. The patients `TCGA-A2-A0ES` and `TCGA-MP-A4T7` appear in **both** original splits. Exclude all images from those patients on the training side before an official test analysis; the supplied nominal split is not patient-disjoint by itself. The [organ mapping source](https://huggingface.co/datasets/RationAI/MoNuSAC/blob/main/gen_script.py) and exact source patient IDs are recorded in the audit.

For the primary matched-tissue evaluation, [`scripts/prepare_monusac_transfer.py --matched-tissues`](../scripts/prepare_monusac_transfer.py) freezes **88 training ROIs from 40 patients** and **32 test ROIs from 19 different patients**, all at least 512 native pixels on each side. Breast (27 train/8 test), kidney (15/10), lung (27/4), and prostate (19/10) occur in both splits. Training patients found anywhere in the original test archive are excluded before the size gate. Some test ROIs have no companion TIFF; the preparation code decodes their organizer SVS at level zero and checks dimensions against annotation metadata. The 3 µm footprint expanded from each expert nucleus is a *proxy* for virtual-marker quantification, not an expert-drawn cell boundary. The [completed 32-image test](https://tkcaccia.github.io/Tambua-Analysis/#matched-cohort) gives 85.2% pooled accuracy and 42.1% four-class balanced accuracy on 10,776 expert nuclei, but recovers only 1/46 macrophages and 0/4 neutrophils. This is conditional classification, not end-to-end CellPhenotyper detection accuracy. The saved model and derived previews retain MoNuSAC's noncommercial share-alike data terms.

The earlier cross-organ pilot trained on **27 lung ROIs from 9 patients** and tested on **10 prostate ROIs from 6 different patients**. Since prostate was absent from training, its [archived result](https://tkcaccia.github.io/Tambua-Analysis/#monusac) is exploratory rather than the matched-tissue benchmark.

MoNuSAC has expert nuclei, not full cell bodies or measured protein. With its expert instance mask as the quantification substrate, the experiment estimates virtual-marker/classifier performance conditional on perfect localization. A second end-to-end endpoint must use CellPhenotyper-detected cells, predeclared instance matching and a count of unmatched detections and references. Never score only easy matched cells without accounting for failures.

## ORION colorectal cancer

The [first-party release](https://github.com/labsyspharm/orion-crc/blob/main/datarelease-README.md) contains registered H&E and 19-channel Orion IF of the same tissue section, computationally generated labelled cell masks and measured marker tables. It is suitable for biological validation of virtual markers and measured-marker-derived cell classes. Full multiplex WSIs are typically 44–147 GiB each, so select bounded registered windows and document all file ranges, coordinates, registration error and patient IDs. The model must be trained on separate patients and evaluated against labels defined from the **measured** channels without looking at virtual GigaTIME outputs. A serial-section dataset must not be used as one-to-one cell truth.

ORION's measured panel includes Pan-CK, CD3e, CD20, CD68 and CD163, which can support carefully gated epithelial, lymphoid and macrophage references. It does not supply an equally specific neutrophil marker, so ORION alone must not be presented as a four-class reference. Define gates, ambiguous-cell exclusions and quality thresholds before viewing virtual-marker predictions; validate the four-class endpoint separately on MoNuSAC or another independently typed cohort.

A bounded local CRC33_01 case was acquired from that public S3 release without downloading the 43.9 GiB IF WSI. Its registered H&E, cell mask and measured-cell table have SHA256 values `e5be3cf68c9adc8bada72a98e681d0ed852abe7b7cbe9b30d4102bea42b9da43`, `fd1b6876c714d37a4391ffd735e1e8a6bed2b52b4ac03c028315894697563aa2`, and `42683f328cedc134426b45179de5e95c2f14481b9e1f6962c729c2362a37a021`. Both OME image planes are 52,740×36,354 at **0.325 µm/pixel**. The reproducible level-zero window `(x=24576, y=39424, width=2048, height=2048)` has 4,104 complete cell IDs and matching measured rows; 226 edge-truncated cells were excluded. The maximum discrepancy between centroids recomputed from the retained masks and published table coordinates was `1.5×10⁻¹¹` pixels. Local files are under `data/orion_crc33_01/window_x24576_y39424_verified/` and ignored by Git. This is an acquisition/alignment check, not marker inference or biological classification. An independent, predeclared phenotyping gate and multiple patients remain necessary for a validation result. The 19-channel IF WSI is deliberately not downloaded to the local machine.

## NuCLS

The [first-party NuCLS repository](https://github.com/PathologyDataScience/NuCLS) contains pathologist-reviewed breast H&E nuclei annotations under CC0. Its ontology and annotation shapes differ from MoNuSAC. Use only after a documented label mapping and a TCGA patient-barcode overlap check.

## Split and metric plan

Lock patient-disjoint train, validation and test IDs before model selection. Treat MoNuSAC's official test patients as untouched test cases except for the explicitly redefined cross-organ pilot, and remove the two overlapping patient IDs from training. Evaluate macro F1 and balanced accuracy as primary descriptive scores, per-class recall/F1 and confusion as secondary, with patient-bootstrap intervals after sufficient patients. Report cell detection/matching, GigaTIME generation, marker quantification, fastPLS fit and inference times separately, plus pixel spacing and marker QC. Compare with majority and measured-marker fastPLS references when ORION is included. Cell-level counts are not independent biological replicates.
